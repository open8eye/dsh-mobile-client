# 界面骨架（导航栏改版）

> 状态：**需求已定稿，尚未实现。** 设计问题已确认，见第四节。

## 一、现在的样子

骨架在 `app/lib/features/home/home_shell.dart`：一个 `IndexedStack` 装四个页面，
底部 `NavigationBar` 四个标签，**每个都带文字**。当前设备那一页自己还有一个
`AppBar`（设备名 + 类型标签 + 刷新 / 设备列表 / 编辑三个按钮）。

```
┌──────────────────────────────────────────────────┐
│  我的台式机  [局域网]          ⟳   ▤   ⚙        │  ← 顶部这一堆，不要了
├──────────────────────────────────────────────────┤
│                                                  │
│                    WebView                       │
│                                                  │
├──────────────────────────────────────────────────┤
│   扫一扫      当前设备      设备列表     设置     │  ← 文字，不要了
└──────────────────────────────────────────────────┘
```

## 二、改成什么样

1. **顶部整条去掉**，WebView 占满剩下的空间。
2. **底部导航栏只留图标，不要文字。**
3. 导航栏从左到右六个位置：

```
┌────────────────────────────────────────────────────────────┐
│                                                            │
│                          WebView                           │
│                                                            │
├────────────────────────────────────────────────────────────┤
│    ⌗       ②        我的台式机        ☰        ⚙       ⟳   │
│  扫一扫   实例数   名称（固定宽度）  设备列表   设置    刷新  │
└────────────────────────────────────────────────────────────┘
```

| # | 内容 | 点击行为 |
|---|---|---|
| 1 | 扫一扫 | 打开扫码页 |
| 2 | **运行实例数** | 显示当前保活的会话个数（连了 1 个就是 `1`，2 个就是 `2`）；点击在它们之间切换 |
| 3 | **当前实例的名称** | **进入这个实例的配置页**（改名、改地址、删除、看类型标签） |
| 4 | 设备列表 | 打开设备列表 |
| 5 | 设置 | 打开设置 |
| 6 | 刷新 | 重新加载当前实例的网页 |

要点：

- **名称那一格宽度固定**（建议 88–96 逻辑像素，`TextOverflow.ellipsis`），
  名字长短不能把整条导航栏顶得忽宽忽窄。
- **设备类型标签（局域网 / Tailscale / 公网）不再显示在主界面**，
  挪进名称点进去的配置页。
- 没有 AppBar 之后 WebView 会顶到状态栏，要留 `SafeArea`。
- 图标要有无障碍标签（`tooltip`），纯图标导航栏对读屏用户是空的。

## 三、「运行实例」的定义与代价

**定义**：这次运行期间**真正保活的会话**。从设备列表点进一台设备就把它加入
「打开的实例」集合，它的 WebView 一直留着；切换是秒切，页面不重新加载、
不用重新登录。计数就是这个集合的大小。

这不是小改动，先把代价说清楚：

- 现在 `DeviceController` 只有一个 `activeDeviceId`，`HomeShell` 只有一个
  `_webViewKey` / 一个 `DshWebView`。要换成 `Set<String> openDeviceIds` +
  一组 WebView（`IndexedStack` 里每个实例一个 `DshWebView`）。
- **每个 Chromium WebView 常驻一份渲染进程，几十 MB 起步。** 老机器上开三四个
  就可能被系统杀掉，所以要有上限（建议 **4 个**）和淘汰策略（最久没看的先关）。
- 通知转发、亮屏保持、前后台判断都要跟着「当前是哪一个」走，不能再用
  单一的 `_index`。
- 关掉一个实例要真的 `dispose` 掉它的 WebView，否则内存只增不减。

**切换方式**（实现时再定）：默认做成点一下弹出已打开实例的列表，选一个切过去；
只有 2 个实例时也可以直接轮换。四个实例的时候轮换不好用，所以默认走列表。

## 四、已确认的决定

| 问题 | 结论 |
|---|---|
| 刷新放哪 | 设置右边再加一个，导航栏共 6 个图标 |
| 「运行实例」指什么 | 真正保活的会话，切换秒切不重载 |
| 中间的名称可点吗 | **可点，点了进入这个实例的配置页** |
| 「编辑设备」入口 | 就是上面这个——点名称进去配置 |
| 去掉顶部的范围 | **只去掉「当前设备」这一页**；设备列表 / 设置 / 诊断 / 关于的标题栏保留（它们同时是返回入口） |

## 六、顺带记下的其它意见

- 顶部那一堆「感觉都不需要」——包括设备名和类型标签，不只是按钮。
- 导航栏文字「也不需要，纯图标就行」。
- 名称要给一个**固定的显示范围**，不要因为名字长短让整条导航栏跳动。
