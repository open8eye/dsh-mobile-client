# 界面骨架（导航栏改版）

> 状态：**已实现。** 设计问题见第四节，实现取舍见第五节。

## 一、现在的样子

骨架在 `app/lib/features/home/home_shell.dart`：一个 `IndexedStack` 装四个页面，
底部 `NavigationBar` 四个标签，**每个都带文字**。当前设备那一页自己还有一个
`AppBar`（设备名 + 类型标签 + 刷新 / 设备列表 / 编辑三个按钮）。

```
┌──────────────────────────────────────────────────┐
│  我的台式机  [局域网]          ⟳   ▤   ⚙        │  ← 顶部这一堆，不要了
├──────────────────────────────────────────────────┤
│                                                  │
│                    WebView                       │
│                                                  │
├──────────────────────────────────────────────────┤
│   扫一扫      当前设备      设备列表     设置     │  ← 文字，不要了
└──────────────────────────────────────────────────┘
```

## 二、改成什么样

1. **顶部整条去掉**，WebView 占满剩下的空间。
2. **底部导航栏只留图标，不要文字。**
3. 导航栏从左到右六个位置：

```
┌────────────────────────────────────────────────────────────┐
│                                                            │
│                          WebView                           │
│                                                            │
├────────────────────────────────────────────────────────────┤
│    ⌗       ②        我的台式机        ☰        ⚙       ⟳   │
│  扫一扫   实例数   名称（固定宽度）  设备列表   设置    刷新  │
└────────────────────────────────────────────────────────────┘
```

| # | 内容 | 点击行为 |
|---|---|---|
| 1 | 扫一扫 | 打开扫码页 |
| 2 | **运行实例数** | 显示当前保活的会话个数（连了 1 个就是 `1`，2 个就是 `2`）；点击弹出一个选择面板，选一个进去 |
| 3 | **当前实例的名称** | **进入这个实例的配置页**（改名、改地址、删除、看类型标签） |
| 4 | 设备列表 | 打开设备列表 |
| 5 | 设置 | 打开设置 |
| 6 | 刷新 | 重新加载当前实例的网页 |

要点：

- **名称那一格宽度固定**（建议 88–96 逻辑像素，`TextOverflow.ellipsis`），
  名字长短不能把整条导航栏顶得忽宽忽窄。
- **设备类型标签（局域网 / Tailscale / 公网）不再显示在主界面**，
  挪进名称点进去的配置页。
- 没有 AppBar 之后 WebView 会顶到状态栏，要留 `SafeArea`。
- 图标要有无障碍标签（`tooltip`），纯图标导航栏对读屏用户是空的。

## 三、「运行实例」的定义与代价

**定义**：这次运行期间**真正保活的会话**。从设备列表点进一台设备就把它加入
「打开的实例」集合，它的 WebView 一直留着；切换是秒切，页面不重新加载、
不用重新登录。计数就是这个集合的大小。

这不是小改动，先把代价说清楚：

- 现在 `DeviceController` 只有一个 `activeDeviceId`，`HomeShell` 只有一个
  `_webViewKey` / 一个 `DshWebView`。要换成 `Set<String> openDeviceIds` +
  一组 WebView（`IndexedStack` 里每个实例一个 `DshWebView`）。
- **每个 Chromium WebView 常驻一份渲染进程，几十 MB 起步。** 老机器上开三四个
  就可能被系统杀掉，所以要有上限（建议 **4 个**）和淘汰策略（最久没看的先关）。
- 通知转发、亮屏保持、前后台判断都要跟着「当前是哪一个」走，不能再用
  单一的 `_index`。
- 关掉一个实例要真的 `dispose` 掉它的 WebView，否则内存只增不减。

**切换方式**：点一下弹出**选择面板**（模态底部弹层），列出所有保活实例，选一个切过去。
不轮换——四个实例的时候轮换不好用，而且面板能让用户看清有哪些、当前是哪个。

- 0 个实例时按钮置灰，点不动。
- 1 个实例时也照样弹面板（里面就一项），行为统一，不用猜。
- 面板里每一项显示设备名 + 类型标签（局域网 / Tailscale / 公网），
  当前那个打勾；顺手可以放一个「关闭这个实例」。

## 四、已确认的决定

| 问题 | 结论 |
|---|---|
| 刷新放哪 | 设置右边再加一个，导航栏共 6 个图标 |
| 「运行实例」指什么 | 真正保活的会话，切换秒切不重载 |
| 中间的名称可点吗 | **可点，点了进入这个实例的配置页** |
| 实例数按钮的切换方式 | **弹出选择面板，选一个进去**（不轮换） |
| 「编辑设备」入口 | 就是上面这个——点名称进去配置 |
| 去掉顶部的范围 | **只去掉「当前设备」这一页**；设备列表 / 设置 / 诊断 / 关于的标题栏保留（它们同时是返回入口） |

### 与最初设想的偏差

- **会话集合没有放进 `DeviceController`，而是单独一个 `SessionSet`。** 它是纯 UI
  会话状态：App 一重启就没有活着的 WebView 了，把它塞进一个负责持久化的
  `ChangeNotifier` 里会让人以为它会被存下来。拆出来还有个好处——LRU 顺序是最容易
  悄悄丢会话的地方，现在它可以脱离 Flutter 单测。
- **上限 4，超了淘汰最久没看的那个。** 每个活着的 WebView 都常驻一个 Chromium
  渲染进程，几十 MB 起步；在老机器上开三四个就可能被系统连整个 App 一起杀掉。
- **密码在 WebView 创建之前读。** 否则会话会先落在登录页、弹一个「请输入密码」，
  而密码其实就在密钥库里。
- **启动时仍然自动打开上次的设备**（与改版前一致），所以实例数一开始就是 1。
- 名称那一格 **88 逻辑像素**；屏幕太窄时按 `maxWidth - 5×40` 给图标让位，
  免得六个槽位在 320dp 的机器上溢出。
- `SessionSet` 的会话是**进程内**的：切换 App 前后台不受影响，杀进程后从 1 个重新开始。

## 六、顺带记下的其它意见

- 顶部那一堆「感觉都不需要」——包括设备名和类型标签，不只是按钮。
- 导航栏文字「也不需要，纯图标就行」。
- 名称要给一个**固定的显示范围**，不要因为名字长短让整条导航栏跳动。
